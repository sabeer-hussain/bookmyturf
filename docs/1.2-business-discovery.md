## Detailed Reasoning

### Q1: Business Domain → Sports Turf
- Fastest-growing SaaS segment in India
- Clear monetization (slot booking)
- Multi-tenant natural fit (each turf owner = one tenant)

### Q2: Revenue Model → Hybrid (Subscription + Commission)
- Predictable recurring revenue from subscriptions
- Scalable income as bookings grow
- Lower entry barrier than pure subscription

### Q3: MVP Scope → Standard
- Lean is too thin to charge subscription
- Feature-rich delays launch
- Standard gives market-ready product in 8-12 weeks

### Q4: Multi-tenancy → Shared DB, Shared Schema
- Lowest infrastructure cost
- Simplest to deploy and maintain
- Sufficient for hundreds of tenants
- Row-Level Security via Prisma middleware

### Q5: Backend → NestJS + TypeScript
- Enterprise-level structure (modules, guards, interceptors)
- Full-stack TypeScript (shared types with frontend)
- Excellent real-time support
- Fastest time-to-market

### Q6: Frontend → Next.js (React + TypeScript)
- SSR/SSG for SEO on public booking pages
- App Router maps naturally to tenant routing
- Single codebase for admin + public pages
- Industry standard for modern SaaS

### Q7: Database → PostgreSQL
- Row-Level Security for tenant isolation
- ACID transactions prevent double-booking
- JSONB for flexible configurations
- Excellent time/date handling for scheduling

### Q8: Hosting → AWS (Amplify + App Runner + RDS)
- Free tier first year ($0 cost)
- No future migration needed
- App Runner = Vercel-like simplicity on AWS
- Scales with business growth
- Chose over Vercel+Railway due to budget concern and long-term scalability

### Q9: Authentication → Phone OTP + Google Social Login
- Indian market prefers phone-based login
- Google as zero-friction alternative
- No password management needed
- Higher conversion rate

### Q10: Payment Gateway → Razorpay
- Route (split payment) for commission model
- Subscriptions API for turf owner billing
- All Indian payment methods (UPI, cards, wallets)
- 2% transaction fee, no setup cost

### Q11: User Roles → 5 Roles
- Real turf businesses have owners + managers + staff
- Manager handles daily ops without full admin access
- Staff does check-ins only
- Simple NestJS Guards implementation

### Q12: Notifications → WhatsApp + Email
- WhatsApp: 98% open rate in India
- Email: formal receipts and reports
- SMS skipped (lower engagement, add as fallback later)

### Q13: Mobile Strategy → PWA
- Next.js already mobile-optimized
- PWA supports push notifications, install prompt
- Customers book via shared links (no app install friction)
- Turf booking isn't daily-use (no dedicated app needed yet)

### Q14: Booking Logic → Hybrid (Fixed + Consecutive)
- Base slots keep calendar clean
- Consecutive booking allows flexibility
- Prevents odd gaps between bookings
- Same model as Playo, Hudle

### Q15: Repo Structure → Monorepo (Turborepo)
- Shared TypeScript types between apps
- Single PR for full-stack features
- Unified CI/CD pipeline
- Ideal for solo developer

### Q16: UI Library → Tailwind CSS + shadcn/ui
- Zero bundle overhead (components copied, not imported)
- Fully customizable per-tenant branding
- Built on Radix UI (accessible)
- Best calendar/date-picker components available

### Q17: URL Strategy → Path-based
- Simplest with Next.js dynamic routes
- No wildcard DNS/SSL needed
- Better SEO (single domain authority)
- Works on free hosting tiers

### Q18: Product Name → BookMyTurf
- "BookMy___" pattern known in India (BookMyShow)
- Zero explanation needed
- Easy to say in conversation
- Memorable after hearing once

### Q19: ORM → Prisma
- Auto-generated TypeScript types
- Best migration system
- Multi-tenant filtering via middleware/extensions
- Largest community for troubleshooting

### Q20: Cancellation Policy → Turf Owner Configurable
- Each business has different dynamics
- Platform provides preset templates (Flexible/Moderate/Strict) + Custom
- Customer sees policy before booking (transparency)
- Refund via Razorpay API automatically

### Q21: Analytics → Standard
- Revenue trends, peak hours heatmap, sport breakdown, retention
- Justifies subscription fee (shows ROI)
- Advanced (predictive) needs data history — Phase 2

### Q22: Multi-sport/court → Multi-court, Multi-sport
- Real turfs have 2-5 courts with different sports
- Each sport needs different slot duration and pricing
- Entity model: Tenant → Venue → Court → CourtSport → Slots

### Q23: Testing → Standard (Unit + Integration + E2E)
- Unit: booking logic, payment calculations
- Integration: tenant isolation verification
- E2E: booking-to-payment flow
- Tools: Jest + Supertest + Playwright

### Q24: CI/CD → GitHub Actions
- Free 2000 min/month
- Native GitHub integration
- Huge marketplace of pre-built actions
- Easy AWS deployment via OIDC

### Q25: Target Market → India, English, i18n Ready
- Launch fast in English
- i18n framework set up from start (next-intl)
- Adding Hindi later = just translation JSON file
- Zero refactoring when expanding

### Q26: Team → Solo Developer + AI
- AI handles boilerplate (CRUD, auth, UI components)
- No coordination overhead
- 10-12 weeks realistic for Standard MVP
- Scale team after product has paying customers

### Q27: Monitoring → Sentry + CloudWatch + BetterUptime
- Every production SaaS needs error tracking + centralized logs
- Sentry: free tier (5K events/month), catches frontend + backend errors
- CloudWatch: AWS-native, logs + alarms + cost alerts
- BetterUptime: uptime monitoring + public status page
- Without these, debugging production issues is blind

### Q28: Security Hardening → Standard
- Helmet.js: security headers on all responses
- @nestjs/throttler: rate limiting per IP + per tenant
- class-validator: input validation on every endpoint
- CORS: restricted to frontend domains only
- Prisma: parameterized queries (SQL injection prevention built-in)
- JWT: short expiry (15min) + refresh token rotation (7 days)
- CSRF: token-based for state-changing mutations
- This level is essential for any payment-handling platform

## Hosting Decision Journey

Initial preference was cheapest option. Here's how we arrived at AWS:

| Option Evaluated | Cost Year 1 | Cost Year 2+ | Verdict |
|-----------------|-------------|-------------|---------|
| Vercel + Railway | ~$60 | ~$55-65/month | Good but requires migration to AWS later |
| Free tier (Vercel Free + Neon Free + Render Free) | $0 | $55-65/month | Cold starts, limited DB, not production-ready |
| AWS (Amplify + App Runner + RDS) | $0 (free tier) | $50-80/month | **Chosen** — same cost, no migration, scales |

**Decision:** AWS wins because free tier covers Year 1, no migration needed at scale, and App Runner provides Vercel-like deploy simplicity without DevOps overhead.
