# BookMyTurf — Slot Configuration Documentation (4.4)

## Overview

Slot configuration (Sprint 4) lets a turf owner define **bookable time slots per court-sport per
weekday**, and lets the system **compute availability** for a given date. It is the data foundation
the booking engine (Sprint 5) builds on.

- **Config unit:** a `SlotConfig` is a recurring **template** for one court-sport on one weekday
  (`dayOfWeek` + `startTime` + `endTime` + `isPeakHour`). It is **not** a dated reservation.
- **Availability:** computed on the fly by expanding a court-sport's active slot configs for a
  date's weekday into a priced grid.
- **Delivered across three issues:** #28 (config CRUD + bulk + validation), #29 (availability
  computation + shared types), #30 (management UI), reconciled/documented in #31.

## Complete Slot Flow

### Data Hierarchy

```
Tenant
 └── Venue (openTime, closeTime)
      └── Court
           └── CourtSport (baseSlotMinutes, pricePerSlot, peakPricePerSlot, maxConsecutiveSlots)
                └── SlotConfig[]  (dayOfWeek, startTime, endTime, isPeakHour, isActive)
```

Slots belong to a **court-sport** (a sport configured on a court), so slot durations and prices are
per-sport: e.g. Badminton = 30-min slots, Cricket = 60-min slots on the same court.

### Owner Journey (End-to-End)

1. Owner opens a Court detail page and clicks **"Configure Slots"** on a court-sport.
2. Lands on the contextual route `/venues/[id]/courts/[courtId]/sports/[courtSportId]/slots`.
3. The weekly grid is generated from the venue's `openTime`/`closeTime` sliced by the court-sport's
   `baseSlotMinutes` (so every cell is base-aligned and within hours by construction).
4. Owner clicks **"Auto-generate week"** (confirms in a dialog) to create a full week of slots, or
   toggles individual cells on/off.
5. Owner marks peak slots (⚡) and removes unwanted ones.
6. Owner uses the **Availability Preview** (pick a date) to see the customer-facing view.

### API Call Sequence (UI)

```
Page load:  GET /venues/:id           (venue hours)
            GET /courts/:courtId       (court-sports)
            GET /court-sports/:csId/slots  (existing configs)
Enable cell:      POST   /court-sports/:csId/slots
Auto-generate:    POST   /court-sports/:csId/slots/bulk   (missing slots only)
Toggle peak/off:  PATCH  /slot-configs/:id
Remove slot:      DELETE /slot-configs/:id
```

## API Endpoints

Base URL: `/v1`. All endpoints require auth. Roles: **TURF_OWNER, TURF_MANAGER** (bulk create =
**TURF_OWNER** only). Responses use the standard envelope `{ success: true, data }` via
`TransformInterceptor`.

### 1. POST /v1/court-sports/:courtSportId/slots

Create a single slot config.

Request:

```json
{ "dayOfWeek": "MONDAY", "startTime": "06:00", "endTime": "07:00", "isPeakHour": false }
```

Response `201`:

```json
{
  "success": true,
  "data": {
    "id": "clx...",
    "courtSportId": "cs...",
    "dayOfWeek": "MONDAY",
    "startTime": "06:00",
    "endTime": "07:00",
    "isPeakHour": false,
    "isActive": true,
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

Errors: `400` (`INVALID_SLOT_RANGE`, `SLOT_OUTSIDE_OPERATING_HOURS`, `SLOT_NOT_ALIGNED`, or DTO
validation), `409` (`SLOT_OVERLAP`), `404` (court-sport not found / wrong tenant).

### 2. GET /v1/court-sports/:courtSportId/slots

List active slot configs for a court-sport, ordered by `dayOfWeek` (Mon→Sun) then `startTime`.

Response `200`: `{ "success": true, "data": [ SlotConfig, ... ] }` (flat array).

### 3. POST /v1/court-sports/:courtSportId/slots/bulk

Bulk create slot configs for the week (**TURF_OWNER only**). **All-or-nothing** — any invalid slot
rejects the whole batch (single transaction).

Request:

```json
{
  "slots": [
    { "dayOfWeek": "MONDAY", "startTime": "06:00", "endTime": "07:00", "isPeakHour": false },
    { "dayOfWeek": "MONDAY", "startTime": "18:00", "endTime": "19:00", "isPeakHour": true }
  ]
}
```

Response `201`: `{ "success": true, "data": [ ...created SlotConfigs ] }`. Max 500 slots per call.

### 4. PATCH /v1/slot-configs/:id

Update a slot config: `startTime`, `endTime`, `dayOfWeek`, `isPeakHour`, or `isActive`.
Time-affecting changes are re-validated (alignment, within-hours, overlap). Re-activating a slot
(`isActive: true`) re-checks overlap.

Response `200`: `{ "success": true, "data": SlotConfig }`.

### 5. DELETE /v1/slot-configs/:id

**Hard delete** a slot config. Safe — bookings are self-contained (`BookingSlot` stores its own
times; no FK to `SlotConfig`), so deleting a config never orphans a booking.

Response `204` (no content).

### 6. Availability computation (service method — no public endpoint in Sprint 4)

`SlotsService.computeAvailability(tenantId, courtSportId, date)` — pure, deterministic. Expands the
court-sport's active slot configs for the date's weekday into a priced grid. Returns
(`docs/2.3-api-design.md` §9 shape):

```json
{
  "date": "2026-06-22",
  "courtSport": { "id": "cs...", "sportName": "Football", "pricePerSlot": 800 },
  "slots": [
    { "startTime": "06:00", "endTime": "07:00", "status": "AVAILABLE", "price": 800 },
    { "startTime": "18:00", "endTime": "19:00", "status": "AVAILABLE", "price": 1200 }
  ]
}
```

> The **public** `GET /public/:tenantSlug/availability` endpoint is delivered in **Sprint 5** and
> reuses this method unchanged. In Sprint 4 every slot is `AVAILABLE` (no bookings yet); a
> booked-slot subtraction seam is wired to mark `BOOKED` in Sprint 5.

## Validation Rules

| Rule               | Detail                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Time format        | `startTime`/`endTime` must be `HH:mm` 24-hour; `startTime < endTime`                                                                                                        |
| Day                | `dayOfWeek` ∈ `MONDAY..SUNDAY` (`DayOfWeek` enum)                                                                                                                           |
| Within venue hours | slot must satisfy `openTime ≤ start < end ≤ closeTime` (same-day)                                                                                                           |
| Alignment          | slot duration must be a **positive integer multiple of `baseSlotMinutes`** (base 60 → 60/120/180 valid; 45 invalid)                                                         |
| No overlap         | slots must not overlap within the **same court-sport + day** (adjacent = OK); validated **inside the transaction** (race-safe — `slot_configs` has no DB unique constraint) |
| Bulk atomicity     | all-or-nothing: one invalid slot rejects the whole batch                                                                                                                    |
| Peak pricing       | `isPeakHour` is a flag; price = `peakPricePerSlot` when set & flagged, else base `pricePerSlot` (Decimal → number)                                                          |

Error codes: `INVALID_SLOT_RANGE`, `SLOT_OUTSIDE_OPERATING_HOURS`, `SLOT_NOT_ALIGNED` (all 400);
`SLOT_OVERLAP` (409); `INVALID_DATE` (400, availability). Delivered as NestJS exceptions carrying a
`code` in the body (consistent with `VENUE_LIMIT_REACHED`). The `{ success:false, error:{ code } }`
envelope documented in `docs/2.3` is not applied to errors — see **Documentation notes**.

## Frontend (Management UI)

- **Route (contextual):** `/venues/[id]/courts/[courtId]/sports/[courtSportId]/slots`, reached via a
  **"Configure Slots"** button on each court-sport card. (Deviation from `docs/2.1`'s standalone
  `slots/page.tsx` sketch — contextual matches the venue→court→sport drill-down.)
- **`slot-picker.tsx`** — weekly grid-toggle (Mon–Sun × base-aligned times from venue hours ÷
  `baseSlotMinutes`). Toggle each cell active/off and peak/off-peak; peak cells amber; peak-price
  hint when no `peakPricePerSlot`.
- **Auto-generate** — builds the week via shared `generateSlots`, **idempotent** (only missing
  slots), off-peak by default, behind a **confirmation dialog** (prevents accidental generation).
- **Per-slot save** — enable → POST, peak/active → PATCH, remove → DELETE (confirm); optimistic UI
  - toasts.
- **`availability-preview.tsx`** — pick a date → resolves weekday → read-only customer view with
  computed prices + "Available" badge (Sprint 4: config-only, all available).
- Client-side validation mirrors the backend via the shared util (invalid input prevented by
  construction). Responsive, accessible, loading skeletons.

## Shared Slot Logic (`packages/shared`)

The pure, framework-free time logic lives in `packages/shared/src/utils/slot-time.ts` — a **single
source of truth** for both API and web:

- `generateSlots(openTime, closeTime, baseSlotMinutes, peakRanges)` — slice hours into base slots
- `resolveWeekday(date)` — timezone-agnostic `YYYY-MM-DD` → weekday (via `Date.UTC`; rejects
  malformed/impossible dates)
- `rangesOverlap`, `findFirstOverlap`, `isWithinOperatingHours`, `isAlignedToBase`,
  `toMinutes`/`fromMinutes`, `HH_MM_REGEX`, `YYYY_MM_DD_REGEX`

The shared package builds to `dist` (CommonJS + declarations) and has its own jest runner; web
consumes it via `transpilePackages: ['@bookmyturf/shared']`.

## Tenant Isolation

Slot configs are scoped through the court-sport chain: `SlotConfig → CourtSport → Court → Venue →
tenantId`. Every service operation verifies ownership via this relation using the JWT-derived
`tenantId` (`@CurrentUser('tenantId')`). A court-sport not belonging to the caller's tenant returns
`404` (not found), so tenant A cannot see, modify, or delete tenant B's slots.

> Note: isolation is enforced **manually** in the service (consistent with Venues/Courts), via the
> JWT-derived `tenantId` and the court-sport ownership chain — not via Prisma middleware.

## Delete Semantics

| Operation                   | Behavior                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| `DELETE /slot-configs/:id`  | **Hard delete** — row removed                                                                           |
| `PATCH { isActive: false }` | **Soft disable** — slot hidden from list/availability, config retained; re-enable with `isActive: true` |

Hard delete is safe because bookings don't reference slot configs (they store their own times).

## Limitations (documented, deferred)

| Limitation                                                  | Status                                                                                                                                                                                                   |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overnight venues (`closeTime < openTime`, e.g. 18:00–02:00) | Not supported in Sprint 4; grid shows a graceful "Unable to generate…" message. Deferred — needs Sprint 5 booking-date design.                                                                           |
| Base-duration change vs. existing slots                     | Changing a court-sport's `baseSlotMinutes` after slots exist can leave stale slots that overlap the new grid (→ `SLOT_OVERLAP` on re-add). Remove stale slots first. Follow-up: clear/regenerate prompt. |
| Cross-sport court contention                                | Two sports on one court can define overlapping availability windows at config time; the real conflict is enforced at **booking time** (Sprint 5, keyed on physical `courtId`).                           |
| Public availability endpoint / real BOOKED status           | Sprint 5.                                                                                                                                                                                                |
