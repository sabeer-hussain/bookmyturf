# BookMyTurf — Venue & Court Management Documentation (4.3)

## Overview

Sprint 3 implements the core domain — venue management, court management, multi-sport configuration per court, and the complete management UI.

- **Venues:** Physical locations owned by a tenant
- **Courts:** Playing areas within a venue (indoor/outdoor)
- **Court-Sports:** Sport configurations per court with independent pricing
- **Sports:** Global master data (platform-wide, not tenant-scoped)
- **Plan Limits:** Subscription enforces max venues/courts per tenant

---

## Complete Management Flow

### Data Hierarchy

```
Tenant (Turf Business)
  └── Venue (Physical Location)
        ├── Name, Address, City, State, Pincode
        ├── Open/Close Time
        ├── Amenities (13 predefined)
        ├── Images (max 5)
        └── Court (Playing Area)
              ├── Name, Indoor/Outdoor, Surface Type
              ├── Dimensions, Max Players
              ├── Images (max 5)
              └── CourtSport (Sport Configuration)
                    ├── Sport (from global list)
                    ├── Price per Slot (₹)
                    ├── Peak Hour Price (₹)
                    ├── Slot Duration (minutes)
                    └── Max Consecutive Slots
```

### Owner Journey (End-to-End)

```
1. Login → /bookings (sidebar visible)
2. Click "Venues" in sidebar → /venues
3. Click "Add Venue" → fill form (name, address, city, state, times, amenities) → Create
4. Venue appears in list → click venue card → /venues/[id]
5. Click "Add Court" → fill form (name, outdoor, artificial turf, 100x50 ft) → Create
6. Court appears in list → click court card → /venues/[id]/courts/[courtId]
7. Click "Add Sport" → select Cricket, ₹800/slot, ₹1200 peak, 60 min → Add
8. Sport config appears with pricing details
9. Repeat steps 5-8 for more courts/sports
10. Owner now has a fully configured venue ready for booking (Sprint 5)
```

### API Call Sequence

```
POST /v1/venues                    → Create venue
GET  /v1/venues                    → List venues (paginated)
GET  /v1/venues/:id                → Venue detail + courts count
POST /v1/venues/:venueId/courts    → Add court to venue
GET  /v1/venues/:venueId/courts    → List courts in venue
GET  /v1/courts/:id                → Court detail + sport configs
POST /v1/courts/:courtId/sports    → Assign sport with pricing
GET  /v1/courts/:courtId/sports    → List sport configs
PATCH /v1/court-sports/:id         → Update pricing/duration
DELETE /v1/court-sports/:id        → Remove sport (hard delete)
PATCH /v1/venues/:id               → Edit venue
DELETE /v1/venues/:id              → Deactivate venue (soft)
PATCH /v1/courts/:id               → Edit court
DELETE /v1/courts/:id              → Deactivate court (soft)
GET  /v1/sports                    → List sports (public, for dropdowns)
```

## API Endpoints

### 1. POST /v1/venues

**Purpose:** Create a new venue for the tenant.

**Auth:** Required (TURF_OWNER only)

**Request:**
| Field | Type | Required | Validation |
|-------|------|----------|------------|
| name | string | Yes | Max 200 chars |
| address | string | Yes | Max 500 chars |
| city | string | Yes | Max 100 chars |
| state | string | Yes | Max 100 chars |
| pincode | string | Yes | 6-digit regex (`/^\d{6}$/`) |
| openTime | string | Yes | HH:mm 24hr (`/^([01]\d|2[0-3]):[0-5]\d$/`) |
| closeTime | string | Yes | HH:mm 24hr |
| phone | string | No | Max 15 chars |
| latitude | number | No | GPS coordinate |
| longitude | number | No | GPS coordinate |
| amenities | string[] | No | Enum array (13 predefined values) |
| images | string[] | No | URL array, max 5, require_tld: false |

**What happens internally:**

1. Extract tenantId from JWT
2. Fetch subscription → validate status is TRIAL or ACTIVE
3. Count active venues for tenant → validate < maxVenues
4. Create venue record with tenantId
5. Return created venue

**Response (201):**

```json
{
  "success": true,
  "data": {
    "id": "cm1...",
    "tenantId": "t1...",
    "name": "SportArena Main",
    "address": "Andheri West",
    "city": "Mumbai",
    "state": "Maharashtra",
    "pincode": "400058",
    "openTime": "06:00",
    "closeTime": "23:00",
    "amenities": ["parking", "floodlights", "drinking_water"],
    "images": [],
    "isActive": true,
    "createdAt": "2026-07-06T..."
  }
}
```

**Error responses:**
| Code | Condition |
|------|-----------|
| 400 | Validation errors (missing fields, invalid pincode/time/amenity) |
| 400 | Unknown fields submitted (whitelist enforcement) |
| 401 | Not authenticated |
| 403 | Wrong role (not TURF_OWNER) |
| 403 | SUBSCRIPTION_INACTIVE (expired/cancelled/past_due) |
| 403 | VENUE_LIMIT_REACHED (active venues ≥ plan maxVenues) |

### 2. GET /v1/venues

**Purpose:** List tenant's venues (paginated).

**Auth:** Required (TURF_OWNER, TURF_MANAGER)

**Query Parameters:**
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| page | number | 1 | Page number |
| limit | number | 20 | Items per page (max 100) |
| search | string | — | Search in name, city, address |
| sort | string | createdAt | Sort field (whitelist: createdAt, name, city, openTime, closeTime) |
| order | string | desc | Sort direction (asc/desc) |

**What happens internally:**

1. Extract tenantId from JWT
2. Build where: `{ tenantId, isActive: true }`
3. If search: add OR filter (name/city/address contains, case-insensitive)
4. Validate sort field against whitelist (fallback to createdAt)
5. Parallel: findMany (with skip/take/orderBy + \_count.courts) + count
6. Return paginated result with meta

**Response (200):**

```json
{
  "success": true,
  "data": [
    {
      "id": "...",
      "name": "SportArena Main",
      "city": "Mumbai",
      "openTime": "06:00",
      "closeTime": "23:00",
      "_count": { "courts": 3 }
    }
  ],
  "meta": { "page": 1, "limit": 20, "total": 2, "totalPages": 1 }
}
```

### 3. GET /v1/venues/:id

**Purpose:** Get venue details with active courts count.

**Auth:** Required (TURF_OWNER, TURF_MANAGER)

**What happens internally:**

1. findFirst where `{ id, tenantId, isActive: true }` + include `_count.courts` (active only)
2. If not found → 404

**Response (200):** Full venue object with `_count: { courts: N }`.

---

### 4. PATCH /v1/venues/:id

**Purpose:** Update venue details.

**Auth:** Required (TURF_OWNER only)

**Request:** Any fields from UpdateVenueDto (all optional, same validation as create).

**What happens internally:**

1. findFirst where `{ id, tenantId, isActive: true }` → 404 if not found
2. Update with provided fields

---

### 5. DELETE /v1/venues/:id

**Purpose:** Deactivate venue (soft delete).

**Auth:** Required (TURF_OWNER only)

**What happens internally:**

1. findFirst where `{ id, tenantId, isActive: true }` → 404 if not found
2. Update `isActive = false`
3. Courts under this venue become invisible (not deleted, just parent is inactive)
4. Active venue count decreases → frees a limit slot

---

### 6. POST /v1/venues/:venueId/courts

**Purpose:** Create a court in a specific venue.

**Auth:** Required (TURF_OWNER only)

**Request:**
| Field | Type | Required | Validation |
|-------|------|----------|------------|
| name | string | Yes | Max 200 chars |
| description | string | No | Max 500 chars |
| isIndoor | boolean | No | Default: false |
| surfaceType | string | No | Enum (7 values) |
| dimensions | string | No | Max 100 chars |
| maxPlayers | number | No | Int, min 1 |
| images | string[] | No | URL array, max 5 |

**What happens internally:**

1. Verify venue exists, belongs to tenant, is active → 404 if not
2. Fetch subscription → validate status TRIAL/ACTIVE
3. Count ALL active courts across ALL active venues for tenant
4. Validate count < maxCourts
5. Create court with venueId

**Error responses:**
| Code | Condition |
|------|-----------|
| 400 | Validation errors (invalid surfaceType, etc.) |
| 403 | SUBSCRIPTION_INACTIVE |
| 403 | COURT_LIMIT_REACHED (count across all venues) |
| 404 | Venue not found (wrong ID or wrong tenant) |

---

### 7. GET /v1/venues/:venueId/courts

**Purpose:** List courts in a venue.

**Auth:** Required (TURF_OWNER, TURF_MANAGER, TURF_STAFF)

**What happens internally:**

1. Verify venue belongs to tenant → 404 if not
2. findMany where `{ venueId, isActive: true }` with `_count.courtSports` (active only)

### 8. GET /v1/courts/:id

**Purpose:** Get court details with sport configurations.

**What happens internally:**

1. findFirst where `{ id, isActive: true, venue: { tenantId, isActive: true } }`
2. Include courtSports (active) with nested sport object (id, name, icon)
3. 404 if not found

**Response (200):**

```json

  "data": {
    "id": "c1...",
    "name": "Court A",
    "isIndoor": false,
    "surfaceType": "artificial_turf",

      {
        "id": "cs1...",
        "sportId": "s1...",
        "baseSlotMinutes": 60,
        "pricePerSlot": "800",
        "peakPricePerSlot": "1200",
        "maxConsecutiveSlots": 3,
        "sport": { "id": "s1...", "name": "Cricket", "icon": "cricket" }
      }
    ]

}
```

### 9. PATCH /v1/courts/:id

**Purpose:** Update court details.

**Auth:** Required (TURF_OWNER only)

**Tenant isolation:** Via `court → venue → tenantId` nested join.

---

### 10. DELETE /v1/courts/:id

**Purpose:** Deactivate court (soft delete).

**Auth:** Required (TURF_OWNER only)

**Effect:** Sets `isActive = false`. Court-sports stay (just invisible). Frees a limit slot.

---

### 11. POST /v1/courts/:courtId/sports

**Purpose:** Add a sport to a court with pricing configuration.

**Auth:** Required (TURF_OWNER only)

**Request:**
| Field | Type | Required | Validation |
|-------|------|----------|------------|
| sportId | string | Yes | Must exist + be active |
| pricePerSlot | number | Yes | Min 0.01 |
| peakPricePerSlot | number | No | Min 0.01 |
| baseSlotMinutes | number | No | Int, min 1, default 60 |
| maxConsecutiveSlots | number | No | Int, min 1, default 4 |

**What happens internally:**

1. Verify court belongs to tenant (via venue join) → 404 if not
2. Verify sport exists and is active → 404 if not
3. Create CourtSport record
4. Catch P2002 (unique constraint: courtId + sportId) → 409

**No subscription check** — sport config is configuration, not a billable resource.

**Error responses:**
| Code | Condition |
|------|-----------|
| 400 | Missing pricePerSlot, zero/negative price |
| 404 | Court not found (wrong tenant) |
| 404 | Sport not found (invalid sportId) |
| 409 | Sport already configured for this court |

---

### 12. GET /v1/courts/:courtId/sports

**Purpose:** List sports configured for a court.

**Auth:** Required (TURF_OWNER, TURF_MANAGER)

**Response:** Array of CourtSport objects with nested sport (id, name, icon).

---

### 13. PATCH /v1/court-sports/:id

**Purpose:** Update sport configuration (pricing, duration).

**Auth:** Required (TURF_OWNER only)

**Updatable fields:** baseSlotMinutes, pricePerSlot, peakPricePerSlot, maxConsecutiveSlots, isActive.

**Cannot change:** sportId (delete and re-add instead).

**Tenant isolation:** Via `courtSport → court → venue → tenantId` nested join.

---

### 14. DELETE /v1/court-sports/:id

**Purpose:** Remove sport from court permanently.

**Auth:** Required (TURF_OWNER only)

**Type:** Hard delete (record removed from database).

**Response:** 204 No Content (empty body).

**Why hard delete:** CourtSport is a configuration junction table with no business history. After deletion, the same sport can be re-added with new pricing.

---

### 15. GET /v1/sports (Public)

**Purpose:** List all active sports (for dropdowns).

**Auth:** Not required (`@Public()` decorator)

**Response:** Array of all active sports ordered by createdAt.

---

### 16. POST /v1/sports (SUPER_ADMIN)

**Purpose:** Add a new sport to the platform.

**Auth:** Required (SUPER_ADMIN only)

**Catches:** P2002 on duplicate name → 409 "Sport with this name already exists"

## Plan Limit Enforcement

### Subscription Plans

| Plan       | Max Venues      | Max Courts      | Max Staff       | Commission |
| ---------- | --------------- | --------------- | --------------- | ---------- |
| Starter    | 3               | 5               | 3               | 8%         |
| Pro        | 10              | 25              | 10              | 5%         |
| Enterprise | 999 (Unlimited) | 999 (Unlimited) | 999 (Unlimited) | 3%         |

### Enforcement Flow

```
Create Venue/Court Request
         ↓
Fetch subscription (getCurrentSubscription)
         ↓
Check status === 'TRIAL' or 'ACTIVE'?
  ├── No → 403 SUBSCRIPTION_INACTIVE
  └── Yes ↓
Count active resources for tenant
  ├── Venues: WHERE tenantId = X AND isActive = true
  └── Courts: WHERE isActive = true AND venue.tenantId = X AND venue.isActive = true
         ↓
Count >= plan limit?
  ├── Yes → 403 VENUE_LIMIT_REACHED / COURT_LIMIT_REACHED
  └── No → proceed with creation
```

### Key Rules

- Deactivated venues/courts do NOT count against limits
- Court count is global per tenant (across ALL venues, not per venue)
- Court-sport creation has NO subscription check (it's configuration)
- Deactivating frees slots immediately

### Soft Delete vs Hard Delete

| Entity     | Delete Type               | Reason                                      |
| ---------- | ------------------------- | ------------------------------------------- |
| Venue      | Soft (`isActive = false`) | Business entity, bookings reference it      |
| Court      | Soft (`isActive = false`) | Business entity, bookings reference it      |
| CourtSport | Hard (record deleted)     | Configuration junction, no business history |
| User       | Soft                      | Business entity                             |
| Tenant     | Soft                      | Business entity                             |

## Tenant Isolation

### How Venues/Courts Are Isolated

```
Venue: tenantId field directly on model
Court: no tenantId → isolated via venue.tenantId join
CourtSport: no tenantId → isolated via court.venue.tenantId nested join
```

### Query Patterns

```typescript
// Venue — direct filter
prisma.venue.findFirst({ where: { id, tenantId, isActive: true } });

// Court — join through venue
prisma.court.findFirst({
  where: { id, isActive: true, venue: { tenantId, isActive: true } },
});

// CourtSport — double join
prisma.courtSport.findFirst({
  where: { id, court: { isActive: true, venue: { tenantId, isActive: true } } },
});
```

### Security Result

- Tenant A cannot see, modify, or delete Tenant B's data
- Returns 404 (not 403) to avoid revealing resource existence
- All endpoints extract tenantId from JWT (not from request body/params)

## Image Upload Flow

### Constraints

| Constraint           | Value                          |
| -------------------- | ------------------------------ |
| Max images per venue | 5                              |
| Max images per court | 5                              |
| Max file size        | 5MB                            |
| Allowed types        | JPEG, PNG, WebP                |
| Allowed folders      | avatars, logos, venues, courts |

### Flow Diagram

```
User selects file(s) in browser
         ↓
Client-side validation (size ≤ 5MB, type = jpeg/png/webp, count ≤ 5)
         ↓
POST /v1/uploads/presigned { fileName, fileType, folder: "venues" }
  → Backend validates type → generates URL
  → Returns { uploadUrl, fileUrl }
         ↓
PUT uploadUrl (raw file binary, Content-Type: image/jpeg)
  → Dev: file saved to apps/api/uploads/venues/uuid.jpg
  → Prod: file uploaded to S3
         ↓
Frontend saves fileUrl in form state → shows thumbnail preview
         ↓
On form submit: images[] array sent with create/update venue/court
```

### Dev vs Production

| Aspect         | Dev Mode                                        | Production                                  |
| -------------- | ----------------------------------------------- | ------------------------------------------- |
| Upload target  | Local filesystem (`apps/api/uploads/`)          | AWS S3 bucket                               |
| File serving   | NestJS ServeStaticModule (`/uploads/`)          | CloudFront CDN                              |
| URL format     | `http://localhost:4000/uploads/venues/uuid.jpg` | `https://cdn.bookmyturf.in/venues/uuid.jpg` |
| URL validation | `require_tld: false` (allows localhost)         | Same setting (prod URLs still valid)        |

## Architecture Decisions

| Decision           | Choice                              | Reasoning                                                          |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------ |
| Forms as modals    | Dialog overlay (not separate pages) | User stays in context, modern SaaS pattern (Linear, Vercel)        |
| Court-Sport delete | Hard delete                         | Junction table, no history needed, unique constraint works cleanly |
| Court limit scope  | Global per tenant                   | Fair — deactivating a venue frees its courts from count            |
| Subscription check | On creation only                    | Edit/deactivate allowed even with expired subscription             |
| Sport config       | No subscription check               | Configuration, not a billable resource                             |
| Sort whitelist     | Array of allowed fields             | Prevents Prisma injection via arbitrary field names                |
| Sport dropdown     | Filters configured                  | UI prevents duplicate; API catches edge case (409)                 |
| Time picker        | 00:00-23:30 dropdown                | Supports 24x7 turfs, no format errors                              |
| Image upload       | Presigned URL (client → S3)         | Backend never handles file bytes, scales infinitely                |
| Old /courts route  | Deleted (not redirect)              | Local only, no users, clean codebase                               |

## Security Measures

| Measure              | Implementation                                        |
| -------------------- | ----------------------------------------------------- |
| Tenant isolation     | Every query joins to tenantId from JWT                |
| Role-based access    | @Roles() decorator + global RolesGuard                |
| Mass assignment      | whitelist: true + forbidNonWhitelisted: true          |
| Sort injection       | Whitelist: createdAt, name, city, openTime, closeTime |
| File uploads         | Client-side + server-side type/size validation        |
